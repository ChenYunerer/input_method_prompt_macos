# 性能与稳定性优化记录

版本：1.9.1（构建 27）；日期：2026-09-21。基于当前工作区和 1.9.0 暂存基线对比，仓库尚无首次提交。

## 检查范围与改动

| 链路 | 问题与处理 | 验证 |
| --- | --- | --- |
| 输入源 / Caps Lock | 确认等待期间比较已提交状态导致重复读取；改为缓存最近观测标志。合并同一轮输入源通知，截止时复用一次读取。 | 完整读取计数、防闪先后两种顺序、取消候选、提交前复核 |
| 输入源恢复 | 通知或截止复核读到 nil 后可能没有新事件触发恢复；新增 0.5 秒低频重试，成功即停止。 | 初始不可用、通知读取失败、截止读取失败、对象释放后无残留读取 |
| 全屏检测 | 系统通知连发重复查询 WindowServer；合并下一轮扫描。启动时先安装资源再通知回调，避免回调禁用后残留定时器。 | 100 条通知只扫描一次、禁用取消排队扫描、回调重入关闭、原生全屏 |
| 全屏图标 | 仅文字改变时也重设窗口位置、字号并重建材质遮罩；现在缓存状态、目标 frame、缩放与遮罩。 | 输入状态连续改变时背景对象与 frame 不变；真正缩放时正确更新 |
| 全屏悬停 | 鼠标不动仍重复构造命中集合；缓存鼠标位置，图标几何变化时重新命中。 | 原有悬停过渡、尺寸/位置调整回归 |
| 鼠标跟随 | 静止隐藏后仍每 0.1 秒查询指针可见性；完全隐藏后暂停，移动或设置改变时重新读取真实状态并恢复。 | 停止读取计数、隐藏后系统指针变化再移动不闪现、改为淡化恢复检测 |
| 鼠标生命周期 | 重复禁用/状态更新会重新开始淡出；增加幂等保护。显示器失效时取消旧动画。 | 重复禁用不会拖延隐藏、迟到回调、状态失效、窗口恢复与资源释放 |
| 屏幕同步 | 每次恢复都重复写刷新率参数；缓存实际请求刷新率，保留窗口跨屏绑定。 | 帧时钟调度、真实 CADisplayLink、跨屏坐标回归 |
| 预览与设置 | 一个滑块刷新三个页，量化值不变也保存并回调；按分类刷新，重复值跳过写入和回调，三种视图复用布局/样式。 | 跨页预览遮罩身份不变、同百分比连续事件零回调、原设置持久化回归 |
| 中央提示 | 重复提交相同窗口坐标；去掉重复移动，对象销毁时关闭浮层。 | 中央动画、重入和析构隐藏 |
| 构建交付 | 直接覆盖旧包后二进制/签名失败会留下半成品；临时构建并验签后替换，失败回滚，同输出加锁。 | 隔离故障注入及真实 release 打包验签 |

已检查入口、登录项与偏好设置的生命周期。登录项系统操作保持现有 API 调用方式；没有证据支持把同步注册任意移动到后台线程，本次不引入该线程模型变更。全屏识别规则、Caps Lock 确认时长、鼠标位置更新频率、透明度与秒数配置均保持原语义。

## 专项对比

同一机器、`swiftc -O`、相同 10,000 次重复样式更新，使用 1.9.0 暂存源码及本次源码分别编译。每轮更新中央背景、常驻大小/背景/状态和鼠标预览大小；统计遮罩对象是否替换。

| 指标 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 两种材质遮罩对象替换次数 | 20,000 | 0 |
| 该循环单次测量用时 | 35.49 ms | 0.85 ms |
| 同轮 100 条输入源通知的完整读取次数 | 100 | 1 |
| Caps Lock 开启样本的完整读取次数（含初始读取） | 8 | 3 |

这是指定重复工作负载的对象分配和调用次数对比，不是实际鼠标端到端延迟、整机 CPU 或帧率提升比例。正常运行仍保留必需的 Caps Lock 标志检查和全屏检测；淡化模式仍检测真实指针可见性。

## 验证与证据

- 常规回归及真实 `NSCursor.hide/unhide`、输入时隐藏模式：292 项 PASS，失败 0。
- 原生全屏独立验证：6 项 PASS，覆盖焦点、可见性、持续移动与退出全屏。
- 性能稳定性专项：支持 `bash app/scripts/test.sh --performance-only`，另覆盖停止轮询后指针变为隐藏再移动的组合路径。
- 已重启并确认运行 1.9.1；重启前后 11 项功能/外观配置逐项一致，输入源诊断正常。
- release 构建和应用签名检查通过。构建脚本支持 `INPUT_PROMPT_APP_DIR` 指定输出。
- 构建脚本隔离 fixture 使用 stub 编译/签名：签名失败、验签失败保持旧包；第二次移动失败恢复旧包且哈希一致；并发第二个构建被拒绝；结束无遗留锁或暂存目录。
- 原始测试日志及微基准位于忽略目录 `app/.build/performance/`；构建故障注入回执位于 `app/.build/build-script-validation/`。

构建脚本遇到 SIGKILL 或断电无法执行 trap，可能留下锁/临时备份；脚本保留现场供核对，不擅自删除未知历史锁。系统指针可见性继续依赖已在本机验证的旧系统接口；特殊自绘透明指针、所有第三方全屏应用与长期运行环境未据此宣称全面覆盖。
